# rideff.com

Marketing website for RIDEFF (Business + Life). Next.js App Router, TypeScript, Tailwind CSS v4, next-intl. Deployed on Vercel (`fra1`).

The design handoff lives in `rideff_web_handoff/` (spec in its `README.md`; the prototype HTML is the reference).

## Develop

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build (all pages static)
npm run lint && npm run typecheck
```

## Routes

| URL | Page |
|---|---|
| `/`, `/en` | BUSINESS (default). `/de` redirects to `/`. `/id` redirects to `/en` (Business has no Indonesian version in the prototype). |
| `/?for=private`, `/en?for=private`, `/id?for=private` | PRIVATE (RIDEFF Life). `src/proxy.ts` rewrites it to the static internal route `/[locale]/life`. |

## Copy and translations

- `messages/de.json` is canonical and hand-written with semantic keys.
- `npm run i18n` generates `messages/en.json` and `messages/id.json` **only** from the handoff tables (`rideff_web_handoff/design/rideff-*-i18n.js`). It lists any string without a table entry and exits non-zero; nothing is machine-translated.
- `messages/invariant.json`: brand names and labels that stay the same in every language. `messages/overrides.json` (optional): translations approved by the owner that are not in the tables.

## Design tokens

Defined in `src/app/globals.css` under `@theme` (colours, fonts, radii, shadows, keyframes), available as CSS variables and Tailwind utilities.

## Environment

See `.env.example`.

| Variable | Effect |
|---|---|
| `NEXT_PUBLIC_CAL_BUSINESS` | Cal.com slug for the Business Erstgespräch (e.g. `rideff/erstgespraech`). Empty: booking opens `mailto:hallo@rideff.com` with the subject "Erstgespräch". |
| `NEXT_PUBLIC_CAL_LIFE_PRIVATE` | Cal.com slug for Life Private (e.g. `rideff/life-private`). Empty: `mailto:` with the subject "Life Private". |
| `NEXT_PUBLIC_PORTAL_LIVE` | `true` links "Kundenportal" to portal.rideff.com; otherwise it shows "Bald verfügbar" and is not clickable. |

## Newsletter (double opt-in)

`POST /api/newsletter` sends a confirmation mail with a signed link (48 h). Only the click on that link (`/api/newsletter/confirm`) adds the address to the provider's list, then redirects to `/newsletter/confirmed` or `/newsletter/expired`. Nothing is stored on our side. Choose the provider with `NEWSLETTER_PROVIDER` (`resend` or `brevo`), see `.env.example`. While it is not configured, the form shows "Das hat gerade nicht geklappt …".

## Blog

Posts are MDX files in `content/blog/` (file name = URL slug) with front matter `title`, `date` (YYYY-MM-DD), `tag` (`business` or `life`) and `excerpt`. German only for now; `/en/blog` and `/id/blog` redirect to `/blog`. The CTA box at the end follows the tag.

## SEO and social images

- Open Graph images: `public/og/og-{de,en,id}.png` (1200×630), rendered once by `npm run og` from the hero headline and tagline in `messages/*.json`. To use designed images, replace the files and keep the names. Every page sets `og:image` (+ width, height, alt) and `twitter:card=summary_large_image`.
- `sitemap.xml` and `robots.txt` are generated by `src/app/sitemap.ts` and `src/app/robots.ts`. `/demo` and the newsletter status pages are excluded.
- No cookies are set (locale and mode live in the URL); Vercel Analytics is cookie-free.
